# AI A · Claude 시작 지시서

학원의 Claude에게 저장소 루트 `CLAUDE_REQUEST_1.md`를 읽고 실행하라고 지시한다.
그 메시지를 보내는 순간부터 30분 타이머를 시작하며, 메시지와 Claude의 첫 응답을
요청 1회로 센다. 아래 내용은 공식 요청 1과 함께 적용되는 전체 운영 규칙이다.

## 시작 전 사람이 확인할 것

- 저장소: `t05-ai-handoff`
- 브랜치: `main`
- 원격 최신 상태를 받은 뒤 작업한다.
- Claude 화면에 표시된 정확한 모델명을 확인할 수 있게 준비한다.
- 검사 문구와 예산은 작업 도중 바꾸지 않는다.
- 시간은 벽시계로 센다. 첫 요청을 보낸 시각을 적어 두고, 자리를 비운 시간도 포함한다.

## 전체 운영 규칙

```text
당신은 T05 인계 실험의 AI A인 Claude다. 이 저장소에서만 작업한다.

목표는 T03 ALTER / EGO에 "원본 ↔ 카드 비교 슬라이더"의 첫 구현을 만들고,
계획된 시점에 작업을 멈춘 뒤 다음 AI가 대화 없이 이어갈 수 있는 인계 문서를 남기는 것이다.

요청을 이렇게 나눠 쓴다. 중단 시점(3번째 응답 또는 30분)은 그대로다.

- 요청 1: 아래 셋업 넷을 끝내고, 구현은 검사 1 하나에만 손을 댄다.
- 요청 2: 구현에 쓴다. 검사 2와 3을 동작시키고 관련 자동 검사를 남긴다.
- 요청 3: 중단 절차에 쓴다. 아래 `멈추기 전에는` 항목이 그 내용이다.

요청 1의 셋업은 다음 넷이다.
1. docs/EXPERIMENT_PLAN.md와 docs/AI-A-LOG.md를 읽는다.
2. 현재 한국 시각, Claude 화면에 표시된 정확한 모델명, `git rev-parse HEAD` 결과를
   docs/AI-A-LOG.md에 시작 정보로 기록한다. 모델명은 추측하지 않는다.
3. git status와 기존 구조를 확인하고, 사용자의 기존 변경을 보존한다.
4. 기준 테스트와 빌드를 실행하고 결과를 기록한다.

기록은 짧게 적는다. 요청 1에서 검사 2·3까지 끝내려 하지 마라 — 셋업을 서둘러
넘기고 구현을 몰아넣으면 기준선이 부실해지고, 그 기준선은 다시 잴 수 없다.

구현 범위와 고정 검사 10개는 docs/EXPERIMENT_PLAN.md를 그대로 따른다. 검사 문구·번호,
요청 예산, 계획 중단 시점을 유리하게 수정하지 마라. 기존 카드 렌더러 디자인과 PNG 출력,
되돌리기/다시하기, 템플릿 저장 구조를 불필요하게 바꾸지 말고 기존 구조에 맞는 가장 작은
수직 기능부터 구현하라. 우선순위는 검사 1~3을 실제로 동작시키고 관련 자동 검사를 남기는 것이며, 위 요청 배분대로 나눠 한다.

매 응답이 끝날 때 docs/AI-A-LOG.md의 해당 요청 행에 누적 분, 한 일, 실제로 실행해 통과한
검사 번호, 남은 오류, 사람이 직접 바꾼 것을 기록하라. 실행하지 않은 검사는 통과했다고 쓰지 마라.

이 대화의 세 번째 응답이 끝나거나 누적 30분이 되는 때 중 먼저 도달한 시점에 반드시 멈춘다.
누적 30분은 사람이 첫 요청을 보낸 시각부터 흐른 벽시계 시간이며, 응답을 기다린 시간과
사람이 자리를 비운 시간을 빼지 않는다. AI-A-LOG.md의 누적 분도 같은 시계로 적는다.
기능을 더 완성할 수 있어도 계속 구현하지 않는다. 멈추기 전에는 다음을 수행하라.
- 관련 테스트와 빌드를 실행하고 사실대로 AI-A-LOG.md를 마무리한다.
- 현재 구현을 커밋한다.
- docs/HANDOFF.md의 일곱 항목을 구체적으로 모두 채운다. 다음 AI는 이 대화를 볼 수 없다.
- 인계 문서와 기록을 별도 커밋하고 원격 main에 푸시한다.
- 마지막 응답에는 요청 횟수, 누적 시간, 마지막 커밋, 통과 검사 번호, 남은 오류,
  다음 AI가 가장 먼저 할 한 가지를 짧게 보고한다.

트러블슈팅은 네가 한다. 설치 실패, 테스트·빌드 오류, 포트 충돌, 경로나 실행 환경 문제는
AI A인 네 몫이다. 사람에게 명령을 대신 실행해 달라고 하거나 오류 로그를 붙여 달라고 하지 마라.
직접 실행해서 원인을 찾고 고친 뒤, 무엇이 막혔고 어떻게 풀었는지를 AI-A-LOG.md에 적는다.
막힌 것을 못 푼 채 넘어가야 한다면 추측으로 덮지 말고 증상과 시도한 것을 그대로 남긴다.
사람만 할 수 있는 일(계정·권한·결제처럼 저장소 밖의 것)일 때만 요청하고, 그 경우에는
`사람이 바꾼 것` 칸에 기록한다.

docs/AI-B-LOG.md와 docs/FINAL_COMPARISON.md는 수정하지 마라. 비밀값을 추가하지 말고,
범위를 벗어난 리팩터링이나 새 기능도 하지 마라. 추가 질문 없이 저장소에서 확인 가능한 것은
직접 확인하며 진행하라. 지금 요청 1 작업을 시작하라.
```

## 계획 중단 뒤 사람이 할 것

1. Claude의 마지막 커밋과 원격 푸시를 확인한다.
2. Claude 대화 전문이나 별도 요약을 Codex에 전달하지 않는다.
3. 집에서 새 Codex 세션을 열고 저장소를 최신 상태로 받은 뒤,
   `docs/HANDOFF.md`만 시작 문서로 지정한다.
4. **AI B에게 `docs/AI-A-LOG.md`를 읽지 말라고 먼저 지시한다.** 그 파일은 저장소
   안에 있어 지정하지 않아도 열 수 있고, 내용이 AI A의 요청별 요약이라 읽는 순간
   인계 문서만으로 이어갈 수 있는지를 재는 실험이 성립하지 않는다.
   `HANDOFF.md`·`EXPERIMENT_PLAN.md`·코드·테스트는 읽어도 된다.
5. 사람이 추가로 설명해야 했다면 `docs/AI-B-LOG.md`에 재작업으로 기록한다.
   AI B가 `AI-A-LOG.md`를 읽었다면 그 사실도 같은 곳에 남긴다.
