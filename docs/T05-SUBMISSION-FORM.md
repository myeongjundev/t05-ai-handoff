# T05 제출 화면 기록

제출 폼에 실제로 표시된 항목과 안내 문구를 그대로 옮긴 것이다. 과제 요구사항
문서(`T05-SUBMISSION-REQUIREMENTS.md`)가 아니라 **제출 화면 자체의 규칙**이다.

## 제출 준비 · 결과와 확인 방법을 남겨 주세요

> 공개 결과물 URL과 소스 저장소 URL이 모두 필수이며 확인 파일은 선택입니다.
> 재현·통과·확인 4가지와 AI·내 판단 3줄을 적습니다. 형식이 어긋나도
> 제출·승인을 차단하지는 않습니다.

`▶ 선택 과정 기록 남기기 · 제출과 승인에는 영향 없음` (접힘 영역)

### 1. 결과물 URL — **필수**

- 입력 예시: `https://`
- 조건: 제출하는 모든 URL은 **계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA
  없이 새 시크릿 창에서 열려야** 한다.

### 2. 소스 저장소 URL — **필수**

- 입력 예시: `https://github.com/owner/repo/commit/전체-cc…`
- 조건: **브랜치나 저장소 첫 화면이 아니라**, 전체 소스 상태를 다시 받을 수 있는
  **40자리 또는 64자리 소문자 full commit이 포함된 HTTPS 고정 URL**을 적는다.

### 3. 재현·통과·확인 4가지 — 권장

```
어디로 가나요: 공개 결과물 URL
무엇을 하나요(3단계 이내): 1) … 2) … 3) …
무엇이 보이면 통과: …
안 될 때: …
```

> 네 항목은 후행 채점의 평가 기준입니다. 이 형식을 그대로 따르지 않아도 제출
> 자체와 강사·마스터 승인 흐름은 막지 않습니다. 다만 비워 두면 후행 채점에서
> 이 평가 항목이 기록 없음으로 반영됩니다.

### 4. AI와 내 판단 3줄 — 권장

```
AI에게 맡긴 일: …
내가 판단한 일: …
AI 말을 안 들은 일: … (없으면 그 이유)
```

> 세 줄은 후행 채점의 평가 기준입니다. 형식 미준수로 제출·승인을 차단하지는
> 않습니다. 다만 비워 두면 후행 채점에서 이 평가 항목이 기록 없음으로 반영됩니다.

## 확인할 파일 선택 — 선택 사항

- 안내: `과제 결과를 확인할 파일을 선택하세요`
- 낼 수 있는 형식: PDF, DOCX, XLSX, PPTX, TXT, MD, CSV, JSON, HTML, HTM, CSS, JS,
  MJS, PNG, JPG, JPEG, WEBP, ZIP
- **선택한 파일은 비공개로 업로드된다.** 학생은 자기 파일만, 담당 강사와 운영자는
  담당 대상 학생의 파일만 볼 수 있다.
- 한 번에 **10개·합계 8MB**까지 올릴 수 있다.

## 제출 조건과 흐름

- 과제 제출은 **시간과 장소에 관계없이** 언제든 할 수 있다. 강의장 실습 시간은
  프리미엄 연결에만 적용된다.
- **결과 주소 또는 제출 파일 중 하나는 반드시 넣어야 한다.**
- 버튼: `과제 제출`
- 승인 흐름: `제출 → 강사 승인 → 마스터 승인`
- 현재 상태 표시: `과제를 시작했습니다.`

## 이 프로젝트에 바로 걸리는 점

소스 저장소 URL이 **full commit 고정 URL**을 요구한다. 저장소 첫 화면
(`https://github.com/myeongjundev/t05-ai-handoff`)은 조건에 맞지 않는다.
제출 시점의 커밋 전체 SHA를 붙인 형태로 적어야 한다.

```
https://github.com/myeongjundev/t05-ai-handoff/commit/<40자리 full SHA>
```

`docs/AI-B-LOG.md`의 AI B 시작 커밋도 실제 저장소에서 다시 확인한 전체 SHA
`ec93fe1a8f0b7bb9b3181f461dc79cd8c2ed9310`으로 기록한다. 채점자가 각 SHA로
소스 상태를 되받을 수 있어야 한다.
