# T05 · 30초 검증 안내서

## 어디로 가나요

[T05 공개 주소](https://myeongjundev.github.io/t05-ai-handoff/)를 연다. 첫 화면에서
`제작 도구로`를 누르면 Studio로, `T05 결과`를 누르면 AI 인계 결과로 바로 이동한다.

## 무엇을 하나요

1. **샘플 적용** — Studio에서 `샘플로 30초 체험`을 누른다.
2. **비교 열기** — `결과 확인`의 `보기` 메뉴에서 `원본과 비교`를 누른다.
3. **경계 이동** — 흰 경계선을 끌거나 방향키·Home·End를 눌러 0~100을 확인한다.

## 무엇이 보이면 통과인가요

- 경계선 왼쪽의 원본과 오른쪽의 완성 카드 비율이 숫자와 함께 바뀐다.
- Home은 0, End는 100으로 이동하고 값을 벗어나지 않는다.
- 첫 화면의 `T05 결과`에서 AI A → HANDOFF → AI B, 검사 10/10과 다음 선택 기준이 보인다.
- 비교를 닫아도 다운로드 PNG, 템플릿과 되돌리기 결과에는 비교 상태가 섞이지 않는다.

## 안 될 때

- `원본과 비교`가 비활성화되어 있으면 먼저 `샘플로 30초 체험`을 누른다.
- `보기` 메뉴가 닫혀 있으면 미리보기 위 `보기 ▾`를 눌러 펼친다.
- 공개 화면이 이전 모습이면 새로고침한 뒤 다시 확인한다.
- 로컬 전체 검증이 필요하면 Chromium 설치 후 `npm.cmd run verify:handoff`를 실행한다.

## 인계 결과 확인

페이지 아래 `AI HANDOFF EXPERIMENT`에서 다음을 확인한다.

- AI A · Claude: 11분, 요청 3회, 검사 1~3 뒤 계획 중단
- `HANDOFF.md`: 일곱 항목, 사람의 추가 설명 0회, 문서 수정 0회
- AI B · Codex: 8분, 요청 1회, 검사 4~10과 전체 회귀 검증
- 최종 결과: 고정 검사 10/10, 단위 85/85, 브라우저 e2e 38/38

## 평가자가 놓치지 않아야 할 점

AI A의 3개와 AI B의 7개는 속도 경쟁 점수가 아니라 처음부터 나눈 역할이다. 이
실험의 핵심 결과는 AI B가 첫 대화를 받지 않고도 남은 작업을 끝냈고, 사람이 구현
내용을 다시 설명하거나 코드를 재작업하지 않았다는 점이다.

과정 중 AI B가 금지 규칙을 읽기 전에 AI A 로그를 연 절차 오류 1건도 공개 기록에
남겼다. 다음 실험에서는 HANDOFF뿐 아니라 받는 AI 전용 시작 지시서를 함께 만든다.

## 자동 검증

```powershell
npm.cmd run verify:handoff:evidence
npm.cmd run verify:handoff
```

첫 명령은 필수 인계 자료 10개, 보호 문서 5개와 역할이 분리된 핵심 커밋 5개를
빠르게 확인한다. 두 번째 명령은 같은 증거 검사에 단위 85건, 빌드와 Chromium
e2e 38건까지 이어서 실행하며 검사 개수가 달라도 실패한다.

CI에서는 성공 결과를 Actions 요약 표로 남기고, 배포 산출물에도
[`handoff-verification.json`](https://myeongjundev.github.io/t05-ai-handoff/handoff-verification.json)을
포함한다. JSON의 커밋 값과 현재 배포 커밋을 대조하면 어떤 코드가 검증됐는지 확인할
수 있다.

## 제품 정리 판단 확인

공개 화면의 `06 / POST-EXPERIMENT PRODUCT DECISION`에서 3열 구조와 선택한
Canvas-first 2열 구조를 비교한다. 기능 삭제 없이 주요 구역 23→약 14, 반복 안내
8→3, 미리보기 조작 줄 3→1로 줄였고, 같은 85/38 회귀 검사를 다시 통과했다.
