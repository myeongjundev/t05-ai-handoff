## 판단과 구현

1. Studio를 `400px + minmax(0, 1fr)` 2열로 바꿨다. 세 번째 열의 템플릿은
   삭제하지 않고 편집기 마지막 접이식 묶음으로 옮겼다.
2. Hero에 복제돼 있던 사진·문구 입력은 제거했다. 실제 편집 상태를 바꾸는
   입력은 Studio 한 곳에만 남겨 시작 지점을 분명하게 했다.
3. 미리보기의 비율, 실행 취소/다시 실행, 보기, 공유, 다운로드를 한 툴바로
   합쳤다. 덜 자주 쓰는 비교·쇼케이스·안전 영역과 복사 기능은 네이티브
   `details` 메뉴 안으로 이동했다.
4. 캔버스의 렌더 크기나 PNG 생성은 건드리지 않고 CSS 표시 높이만 70vh로
   키웠다. 비교 overlay와 편집 상태의 경계도 그대로 유지했다.
5. Persona 카드는 한국어 이름과 한 줄 설명만 보이도록 압축했다. 영문 이름,
   시대, 추천 비율은 접근 가능한 이름과 `title`에 남겨 정보 자체는 잃지 않았다.
6. 게시 전 확인은 세로 목록에서 가로 스트립으로 바꿨다. 390px에서는 두 칸
   그리드로 접혀 읽기 순서를 유지한다.

## 후속 보강 · 인계 검증 명령

평가자가 Git 기록을 일일이 대조하지 않아도 되도록 `npm run verify:handoff`를
추가했다. 필수 자료 10개, 보호 문서 5개의 정규화 해시, 역할이 분리된 핵심
커밋 5개와 그 선후 관계를 먼저 검사한다. 이어서 단위 85개, 빌드, Chromium
E2E 38개를 실행하고 테스트 개수까지 정확히 일치해야 성공한다.

CI는 전체 Git 기록을 받은 뒤 빠른 `verify:handoff:evidence`를 먼저 실행한다.
따라서 문서가 사라지거나 보호 본문이 바뀌거나 인계 커밋이 없는 소스 묶음은
테스트가 통과하더라도 배포 단계로 넘어가지 않는다.
